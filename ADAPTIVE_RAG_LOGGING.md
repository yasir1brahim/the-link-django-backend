# Adaptive RAG Logging

## Overview
Comprehensive logging has been added to track agent decisions and tool calls in the adaptive RAG implementation.

## Log Output Format

### 1. Agent Start
When the agent begins processing a query:

```
================================================================================
🤖 ADAPTIVE RAG AGENT START
================================================================================
User query: 'What are the concrete requirements?'
Chat ID: 123
Max iterations: 4
================================================================================
```

### 2. Tool Call (when agent decides to retrieve)
Each time the agent calls the `retrieve_documents` tool:

```
================================================================================
🔍 ADAPTIVE RAG TOOL CALL
================================================================================
Query: 'concrete mix design requirements'
Documents requested: 5 (capped at: 5)
Project: abc-123, Version: xyz-789
Documents retrieved: 5
Top sections retrieved:
  1. Section 033000 (concrete_spec.pdf)
     Preview: The concrete mix shall have a minimum compressive strength of 4000 psi at 28 days...
  2. Section 033001 (concrete_procedures.pdf)
     Preview: Consolidate concrete during placement operations so concrete is thoroughly worked...
  3. Section 033005 (concrete_curing.pdf)
     Preview: Cure concrete for minimum 7 days using approved curing methods...
================================================================================
```

### 3. Agent Completion
When the agent finishes processing:

```
================================================================================
✅ ADAPTIVE RAG AGENT COMPLETE
================================================================================
Tool calls made: 2
Total sources retrieved: 10
Answer length: 425 characters
================================================================================
```

### 4. No Retrieval Case
When agent decides NOT to use the tool:

```
================================================================================
✅ ADAPTIVE RAG AGENT COMPLETE
================================================================================
Tool calls made: 0
Total sources retrieved: 0
ℹ️  Agent decided NOT to retrieve documents (query didn't require project specs)
Answer length: 45 characters
================================================================================
```

## What You Can Learn from Logs

### 1. Query Analysis
See how the agent interprets and reformulates queries:
- Original user query
- Search queries generated by the agent
- Number of documents requested for each search

### 2. Retrieval Decisions
Understand when and why the agent retrieves:
- Simple queries like "hello" → 0 tool calls
- Specific questions → 1-2 focused tool calls
- Complex questions → Multiple tool calls with different queries

### 3. Document Selection
Track which documents are being retrieved:
- Section numbers (MasterFormat codes)
- Source file names
- Preview of content
- Actual number of documents retrieved vs requested

### 4. Performance Metrics
Monitor efficiency:
- Total sources retrieved per query
- Number of tool calls (iterations)
- Answer length
- Whether retrieval was necessary

## Monitoring Best Practices

### 1. Check Query Reformulation
- Are the agent's search queries focused and relevant?
- Is the agent breaking down complex queries appropriately?

### 2. Validate Document Counts
- Is the agent requesting appropriate numbers of documents?
- Is it respecting the dynamic k-value guidance (3-5 for simple, 5-8 for moderate, 8-10 for complex)?

### 3. Track Retrieval Patterns
- What percentage of queries require retrieval?
- Average number of documents retrieved per query
- Average number of tool calls per query

### 4. Identify Issues
- Queries that should retrieve but don't
- Queries that retrieve too many/too few documents
- Repeated retrievals with similar queries (inefficiency)

## Log Location

Logs appear in:
- **Docker logs**: `docker-compose logs -f web`
- **Django console**: When running locally
- **Application logs**: Check your logging configuration

## Performance Impact

The logging is print-based and has minimal performance impact:
- ~1-2ms overhead per log statement
- Negligible compared to LLM and vector store calls
- Can be disabled by commenting out print statements if needed
